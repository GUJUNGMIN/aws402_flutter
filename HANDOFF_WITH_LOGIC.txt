1. 전달 문서
HANDOFF_LOGIC.html: 브라우저에서 인터넷 없이 여는 전체 연결도·근무 상태도·기능 매핑.
SOURCE_INDEX.txt: 소스별 역할과 함수 위치(코드 정렬 완료 후 줄 번호).
WATCH_HANDOFF.txt: API 입력/응답·검증·운영 조건의 상세 기준.
HANDOFF_CHANGE_REPORT.txt: 이번 주석 보완 및 검증 결과.
자동 생성 다국어 l10n Dart 파일은 재생성 대상이므로 주석 추가에서 제외했습니다.
test는 자동 검증, lib는 실제 앱 코드입니다. 기존 테스트는 보존했습니다.

2. 구현 범위
실제 워치 이벤트 수신 계약 → 서버 전송 → 기존 테이블 저장/판정 → 저장값 응답 → 앱 갱신 경로가 준비돼 있습니다.
워치 SDK/워치 앱/플랫폼 채널/센서 권한·백그라운드 수신은 담당자가 연결해야 합니다.
기본 WatchClient는 미설정이며 연결 성공·가상 수치를 만들지 않습니다.
외부 전화·담당자 메시지·SOS는 이번 구현 완료 범위가 아닙니다.

3. 건강 측정 한 건의 처리 순서
(1) 실제 연결 이벤트 → WatchBridgeClient.reportConnection.
(2) 실제 세 센서 묶음 + 고유 ID + 실제 측정 시각 → reportMeasurement.
(3) WatchHealthController._receive: 형식·신선도·순서·요청/연결 이후 시각 검사.
(4) MobileApi.sendMeasurement: 전송 직전 휴대폰 GPS를 선택 첨부.
(5) POST /api/mobile/measurements: X-Mobile-Session으로 사용자 결정.
(6) MobileMeasurementService.receive: TYPE.WS 행 잠금, 최근 중복/역순 검사.
(7) MobileThresholdService.rulesFor: 성별·연령대·마지막 근무 이벤트의 HEALTH_BASE 세 항목 조회.
    마지막 이벤트가 RS일 때만 RESTING, 그 외 WORKING 기준입니다.
(8) MobileRiskService / MobileRiskRules: 낙상 신호 확인 후 위험 > 경고 > 주의 순서 판정.
    어느 경계에도 해당하지 않으면 NORMAL. 판정 경계는 HEALTH_BASE에서 읽습니다.
(9) HEALTH(STEPS=0), 선택 GPS_LIST, 비정상 상태 변경 시 ALERT_LIST를 한 트랜잭션으로 저장.
(10) snapshot: 실제 HEALTH 저장 수치를 다시 조회. 온도는 소수 둘째 자리 저장값.
(11) Flutter가 saved:true·유효 판정·동일 ID/시각을 확인한 뒤 WorkState에 반영.
(12) 같은 HealthMetricCard로 근무 전·중·휴식 화면에 표시.
카드별 상태는 동일한 서버 종합 판정입니다. 개별 센서별 등급을 계산하는 API는 없습니다.
연결 중 최초 NORMAL만 근무 시작 조건을 충족하고 비정상 수치도 저장 확인 후 표시합니다.

4. 기존 ERD와 비영속 정보
테이블·컬럼·기존 ERD SQL은 변경하지 않았습니다. 추가 receipt 테이블은 사용하지 않습니다.
DB에는 기존 건강 수치·선택 GPS·상태 변경 알림·근무 이벤트와 기존 수신/이벤트 시각을 저장합니다.
sampleId·실제 measuredAt·당시 판정·비교 해시·정밀 종료 시각은 제한된 메모리 정보입니다.
기본 보관 185초(120+5+60), 최대 10,000건입니다.
재시작·만료·용량 초과·여러 서버 간 영구 ID 중복 방지는 보장하지 않습니다.
saved:true는 기존 DB 저장 완료이며 응답의 모든 메타데이터가 영구 저장됐다는 뜻이 아닙니다.
health 이력의 호환 measuredAt 필드는 INSERT_TIME(서버 수신 시각)이며 날짜 필터도 수신 기준입니다.
timestampKind=SERVER_RECEIVED, sampleId=null, source=UNKNOWN으로 구분합니다.
latest에서 메모리가 없으면 ID/실제 시각/당시 판정은 null, metadataAvailable:false입니다.
재시작/메모리 소실 뒤 새 근무는 새 측정이 필요합니다. 기존 진행 근무/이력은 DB에 남습니다.
기존 DATETIME 초 정밀도는 유지하며 정밀 종료 시각이 없으면 다음 초까지 보수적으로 재시작을 제한합니다.

5. 근무 단계
READY -- START/WS --> WORKING -- REST/RS --> RESTING -- RESUME/RR --> WORKING
WORKING 또는 RESTING -- END/WE --> READY
서버 전환 검증·저장 성공 후 앱 단계와 상단바를 갱신합니다.
종료 뒤 워치 연결은 유지하고 최초 측정만 초기화합니다.
최신 배정과 실제 진행 배정은 다를 수 있어 MobileActiveWorkService를 공통 사용합니다.

6. 워치 담당자 연결 순서
- watch_client.dart 계약, health_measurement.dart 필드/단위를 확인합니다.
- WatchBridgeClient의 onConnect/onDisconnect/onRequestMeasurement에 SDK 명령을 연결합니다.
- 실제 SDK 연결/해제 이벤트를 reportConnection으로 전달합니다.
- 새 수치 묶음을 재사용하지 않는 sampleId와 실제 measuredAt로 reportMeasurement에 전달합니다.
- lib/main.dart에서 runApp 전에 WatchClient.instance = bridge로 등록합니다.
- 측정 주기(예: 1분)는 워치/SDK가 담당하며 신규 이벤트를 보내야 합니다.
- 과거 값에 현재 시각을 붙이거나 누락/센서 실패를 정상 수치나 0으로 채우지 않습니다.
- 앱은 전송 중 추가 샘플을 보관하지 않고 실패값도 자동 재전송하지 않습니다.
- 명령 Future 완료와 실제 connected를 구분합니다.
- 화면 꺼짐/백그라운드/프로세스 종료·네이티브 구독 해제는 실기기에서 확인합니다.

7. 실행과 전달
공유용: DB_URL/DB_USERNAME/DB_PASSWORD 환경변수 또는 개인 application-local.properties + local 프로필.
개인 설정 포함 ZIP: 정상 접속 local 파일 복사, 프로필 미지정 시 local 기본 적용.
개인 ZIP에는 DB 비밀번호가 있으므로 팀원에게는 공유용 ZIP을 전달합니다.
Java 21 / MySQL: gradlew.bat test bootJar.
Flutter: flutter pub get / flutter test.
실기기: flutter run --dart-define=MOBILE_API_BASE_URL=http://서버IP:8080
에뮬레이터 기본 URL은 http://10.0.2.2:8080입니다.
기존 폴더에 덮어쓰지 말고 새 폴더로 열어 IntelliJ 실행 경로를 확인하세요.
이전 MobileMeasurementSchemaCheck.java와 mobile/entity/MobileMeasurementReceipt.java가 없어야 합니다.
현재 mobile/model/MobileMeasurementReceipt.java는 정상 파일이므로 유지합니다.
새 테이블 SQL은 없으며 TYPE 코드 누락 시 data-only reference_codes INSERT만 선택 확인합니다.

8. 오류 확인
No active profile와 환경변수 이름 그대로의 DB 계정 오류: 실제 계정/프로필 설정 미적용.
mobile_measurement_receipt 누락과 SchemaCheck: 이전 소스/클래스가 섞인 상태.
Started 뒤 Application run failed가 있으면 기동 성공이 아닙니다.
올바른 소스 확인 후 gradlew.bat clean classes로 남은 클래스도 정리합니다.
새 테이블을 만들어 오류를 우회하지 않습니다.
기동 성공과 실제 저장 성공은 별개이므로 아래 실기기 검사를 수행합니다.
