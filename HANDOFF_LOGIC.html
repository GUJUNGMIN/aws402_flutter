4. 워치 담당자가 연결할 위치

  1. 실제 센서 지원·권한·단위를 확인합니다. 심박 bpm, 피부온도 ℃, 산소포화도 %입니다.
  2. WatchBridgeClient의 세 명령 콜백에 실제 SDK 명령을 연결합니다.
  3. 실제 연결/해제 이벤트는 reportConnection, 새 수치 묶음은 reportMeasurement로 전달합니다.
  4. lib/main.dart의 runApp 전에 WatchClient.instance를 실제 브리지로 등록합니다.
  5. 1분 등 합의한 주기로 신규 측정 이벤트를 보내고 실기기 수신·저장·판정을 검증합니다.
final bridge = WatchBridgeClient(
  onConnect: transport.connect,
  onDisconnect: transport.disconnect,
  onRequestMeasurement: transport.requestMeasurement,
);
WatchClient.instance = bridge;

// SDK의 실제 이벤트에서 호출
bridge.reportConnection(WatchConnection.connected);
bridge.reportMeasurement(HealthMeasurement(
  sampleId: incomingUniqueId,
  measuredAt: incomingMeasuredAt,
  bpm: incomingHeartRate,
  temperature: incomingSkinTemperature,
  spo2: incomingOxygenSaturation,
));

transport는 팀원이 구현할 실제 객체의 예시입니다. SDK 명령 완료를 실제 연결로 간주하지 않으며, 누락/실패/권한 거부를 정상 수치나 0으로 대체하지 않습니다. 백그라운드·화면 꺼짐·프로세스 종료 주기는 별도 네이티브 구현과 실기기 검증이 필요합니다.

5. 기존 ERD에서 저장되는 것과 메모리에 남는 것

기존 DB에 영구 저장

  • HEALTH: 심박·소수 둘째 자리 피부온도·산소포화도·수신 시각. STEPS는 0.
  • GPS_LIST: 전송 직전 조회 가능한 선택 좌표.
  • ALERT_LIST: 변경된 비정상 판정의 알림.
  • WORK_LIST: WS / RS / RR / WE 이벤트.

최근 요청용 메모리

  • sampleId·실제 measuredAt·당시 종합 판정·비교 해시.
  • 정밀 근무 종료 시각.
  • 기본 185초, 최대 10,000건.
  • 재시작·만료·용량 초과 시 소실. 서버 간 공유 없음.
saved:true는 기존 테이블의 저장 성공입니다. 모든 응답 필드가 DB에 영구 저장됐다는 뜻은 아닙니다. 영구 ID 중복 방지는 제공하지 않습니다. 추가 테이블·컬럼은 만들지 않습니다.

건강 이력 날짜/시간은 INSERT_TIME(서버 수신 시각)입니다. 호환 measuredAt 필드에도 수신 시각을 주고 timestampKind=SERVER_RECEIVED로 명시합니다. latest에서 최근 메모리가 없으면 실제 시각·ID·당시 판정은 null입니다.

서버 재시작 후 로그인은 같은 세션 폴더를 사용하면 유지됩니다. 최근 측정 검증 정보는 초기화됩니다. 기존 DB 이력/진행 근무는 유지되고 새 근무에는 새 측정이 필요합니다. DB의 초 정밀도는 유지하며 정밀 종료 정보가 없으면 다음 초까지 보수적으로 검사합니다.
